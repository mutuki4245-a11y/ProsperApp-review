# 未送信の注文とカラオケは端末内下書きとして再読込後も復元する

> 実装状況（2026-07-27）: 注文端末と営業中カラオケの端末内下書き、および会計準備中に消去する連携を適用済み。P1受入確認は継続中。

未送信の注文キューと営業中カラオケ数量は、店舗・営業日・伝票に紐付けた端末ごとのlocalStorage下書きとして保持する。画面再読込時にはDBの最新状態と照合し、対象伝票が `open` の場合だけ復元する。

保存成功、利用者の明示破棄、または対象伝票が `checkout_ready`、`checked_out`、`cancelled` など `open` 以外へ変わった場合は下書きを削除する。下書きは端末間で共有しない。

## Considered Options

### 注文キューをページ内メモリだけに置く

現行実装のように再読込で注文が失われ、localStorageを使うカラオケ下書きと復旧方針が分かれる。

### 端末間で下書きを同期する

未送信データの競合、誤送信、共有状態の正を新たに扱う必要がある。注文端末複数台運用でも、共有状態はDB保存後だけとする方針に反する。

### 決定案

利用者の未送信入力は同じ端末・同じ営業日だけで復元し、業務状態はDB保存後にだけ共有する。
