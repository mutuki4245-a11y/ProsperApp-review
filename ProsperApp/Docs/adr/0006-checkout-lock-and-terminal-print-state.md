# 会計準備中はDB状態、印刷状態は会計端末内状態に分ける

> 実装状況（2026-07-27）: 会計伝票・領収書のブラウザ状態管理と関連RPCはリモートDBとEdge Functionへ適用済み。実機印刷確認は継続中。

伝票を編集禁止にする会計準備中は、`store_slips.status = 'checkout_ready'` としてDBで管理する。会計確定は `checkout_ready` から `checked_out` へ遷移するDB操作とする。

会計伝票の印刷待ち、印刷中、印刷失敗、印刷済みは、店舗1台の会計端末にあるlocalStorageで管理する。会計伝票出力の成功後は直ちに印刷を開始し、会計準備中は同じ会計伝票を自由に再印刷できる。紙面に `再印刷` などの表記を付けず、印刷履歴も保存しない。同一ページの会計伝票、領収書、領収書再試行は共有の端末内印字キューで直列化し、SII Web SDK Serverへの同時接続を避ける。領収書の最初の印刷失敗通知と即時再試行も同じ端末内の補助情報とし、物理印刷状態をDBステータスや印刷ジョブテーブルで同期しない。

`checked_out` の確定済み伝票は、端末内通知の有無にかかわらず営業中トップからいつでも領収書を手動再発行できる。印刷データは確定済み伝票と会計・決済の保存データから再生成する。初回印刷失敗後の最初の再試行、または会計確定成功後の応答未達により初回印刷要求を作れなかった後の最初の物理印刷は、初回印刷として扱い追加表記なしとする。`doPrint` 成功時だけ同じ会計端末のlocalStorageへ `checkout_id` ごとの初回成功記録を残し、記録ありで店員が明示的にもう一度出力する場合だけ `再試行` を紙面へ印字する。成功記録がない、または端末内データが消失した場合は初回印刷として扱い、会計取消時は成功記録と失敗通知を削除する。手動再発行は操作上の呼称であり、紙面に `再発行` は印字しない。会計取消済み伝票は再発行できない。

会計伝票の端末内印刷状態は会計確定の条件にしない。会計準備中のモーダルは、再印刷・会計準備解除・決済への移行を提示する。端末記録がない会計準備中伝票は、再印刷用に復旧用RPCから会計伝票を再取得する。

## Considered Options

### 物理印刷状態もDBステータスとして管理する

ブラウザの物理印刷コールバックをDBへ同期する追加RPCと、失敗・タイムアウト・端末再起動時の復旧遷移が必要になる。単一会計端末運用には過剰である。

### 印刷完了を記録せず、キュー削除だけで扱う

再読込後に、印刷済みとlocalStorage消失を区別できず、会計確定の許可判断が不安定になる。

### 決定案

編集禁止と会計確定はDBを正とし、物理印刷の進行だけを端末内状態として保持する。
