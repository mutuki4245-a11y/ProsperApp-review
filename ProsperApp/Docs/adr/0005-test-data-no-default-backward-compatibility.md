# 発行者マスタのサンプル値に既存データ互換を持ち込まない

> 実装状況（2026-07-27）: 発行者列、サンプルseed、スナップショット契約はリモートDBへ適用済み。P1受入確認は継続中。

領収書の会社名、住所、電話番号、店舗ロゴ、適格事業者番号などの発行者情報は `company_master` / `department_master` に持たせ、画面実装前のサンプル値も同マスタへseedしてよい。スキーマやRPC契約を変更するときも、既存行への値補完、旧契約の併存、互換fallbackを既定要件にしない。

既存データを保持する必要がある変更だけ、対象行、移行SQL、検証方法、切替手順を個別に定義する。

## Considered Options

### 既存行を常に補完し旧契約を併存する

サンプルデータにも移行コードと互換分岐が残り、後続実装の変更範囲と検証対象を不必要に増やす。

### 発行者マスタの編集画面が整うまで印字しない

必要な80mm領収書レイアウトと印字項目を確認できない。

### 決定案

画面実装前のサンプル値も発行者マスタへseedし、互換性が必要なデータ移行だけを明示的な実装タスクとして扱う。
