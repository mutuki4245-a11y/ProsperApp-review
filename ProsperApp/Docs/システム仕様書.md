作成日: 2026-07-03

## 1. 文書の位置づけ

本書は ProsperApp のシステム構成、画面、主要コンポーネント、外部連携、RPC/SQL運用を整理する。業務要件は `Docs/要件定義書.md`、作業時の最新方針は `HANDOFF.md` を参照する。

状態区分は以下の通り。

| 状態 | 意味 |
| --- | --- |
| 実装済み | 現行コード、DB、または運用設定に実装が確認できる仕様 |
| 方針 | 現行方針として維持する仕様 |

## 4. 認証・認可

| 項目 | 状態 | 仕様 |
| --- | --- | --- |
| 認証方式 | 実装済み | Cookie認証を既定schemeとし、Google OAuth設定がある場合はGoogleをchallenge schemeにする。 |
| Google設定不足 | 実装済み | `GoogleDrive:ClientId` または `GoogleDrive:ClientSecret` が不足する場合、Google challengeを開始しない。 |
| 許可判定 | 実装済み | `GoogleAuthOptions.IsAllowed` が `AllowedEmails` と `AllowedDomains` を照合する。 |
| Cookie検証 | 実装済み | Cookie principal検証時にGoogle設定または許可条件を満たさない場合、principalをrejectしてSessionをclearする。 |
| Google token | 実装済み | Google access tokenは認証ticket作成時にSessionの `GoogleDriveAccessToken` へ保存する。 |
| 認可 | 実装済み | `MapRazorPages().RequireAuthorization()` によりRazor Pageを原則認証必須にする。`/Login` はPageModelの `[AllowAnonymous]` で認証前アクセスを許可する。 |
| logout | 実装済み | `/logout` はSessionをclearし、Cookie認証をsign outする。returnUrlはローカルURLのみ許可する。 |

### 6.1 画面UI変更方針

| 領域 | 状態 | 仕様 |
| --- | --- | --- |
| 勤怠キャスト追加 | 実装済み | `/Closing/Attendance` のキャスト追加モーダルは、有効キャストをチェックボックス一覧で表示し、複数名を一括で出勤登録できるようにする。既に当日勤怠があるキャストは重複登録しない。 |
| 勤怠時刻選択 | 実装済み | 勤怠入力の出勤時刻は19:00、退勤時刻は24:00をUI初期値にする。時刻選択肢はそれぞれの初期値を中心に前後12時間を表示し、刻みは `AttendanceMinuteStep` に従う。24:00以降の時刻はアプリ内では25:00、26:00のように表記する。 |
| 指名追加 | 実装済み | `/Slips/Edit` の指名追加では、指名種別のデフォルトを本指名にする。同伴は「19:29まで」「19:59まで」「20:59まで」「21:00以降」の4種類として扱う。 |
| 指名価格 | 実装済み | 指名追加UIでは指名種別の次に指名価格の選択UIを置き、1000円から20000円まで1000円刻みで毎回選択できるようにする。指名価格は会計額に加算する。後続仕様で、指名種別に応じたキャストバックを追加できる余地を残す。 |
| 指名候補キャスト | 実装済み | 指名追加のキャスト候補は、退勤済みかどうかに関わらず、当日出勤キャスト全員を表示する。 |
| 自由入力明細 | 実装済み | 伝票には通常の商品明細とは別枠で、名前と価格を自由入力できる調整明細を追加できるようにする。商品マスタには登録せず、価格は負値を許容し、当面は税区分や商品売上分類に分解せず会計合計額へ直接加減する。伝票/会計では通常商品とは別の明細グループとして表示する。 |
| `/Orders` 複数卓キュー | 実装済み | `/Orders` の注文キューは行ごとに対象卓または対象伝票を保持し、違う卓のオーダーも同じキューに入れて一括登録できるようにする。登録時は注文行ごとの `slip_id` を含めて `add_store_order_lines` を呼ぶ。 |
| バックキャスト候補 | 実装済み | バック対象商品のバックキャスト選択候補は、先頭に「なし」を表示する。「なし」を選んだ注文行にはバックの摘要を付与しない。候補キャストは退勤済みかどうかに関わらず、当日出勤キャスト全員を表示する。 |
| 営業中会計額 | 実装済み | 営業中画面では卓ごとの会計額を常に隠し、画面右下寄りに固定表示する専用オーバーレイボタンに触れている間だけ会計額が見えるようにする。触れていない状態では会計額を静的テキストとして表示しない。 |
| カラオケ簡易入力 | 実装済み | 営業中画面と伝票詳細ではカラオケを通常の商品明細とは別枠で簡易入力できるようにし、伝票行の `+` / `-` ボタンで数量を増減できるようにする。営業中画面では数量変更を即時表示し、手動保存ボタンを置かず、短時間のデバウンス後に差分だけ自動保存する。伝票詳細へ遷移する前にも未保存分の保存を短く試みる。カラオケは1回200円固定とし、伝票/会計では通常商品とは別の明細グループとして表示する。商品マスタには登録せず、数量が0になった未登録行はキューから除外し、負の数量にはしない。 |
| 会計時領収書印刷 | 一部実装 | 会計確定時に、SII製レシートプリンター向けの領収書印刷要求を作成できるようにする。ブラウザから直接プリンターを制御せず、`ReceiptPrinter` 設定の端末側ブリッジURLへHTTP POSTする。印刷失敗時も会計確定は完了扱いとする。領収書レイアウト、印字項目、再印刷画面、正式APIは別途定義する。 |

### 6.2 現場操作性・レスポンス改善 実装方針

現場投入で効果が大きいものに絞り、先に共通実装を作ってから注文、カラオケ、自由入力明細へ適用する。

| 優先 | 状態 | 実装方針 |
| --- | --- | --- |
| 1 | 実装済み | POST送信共通部品を作る。対象は注文登録、勤怠保存、会計確定、自由入力明細保存、伝票詳細のカラオケ数量保存。押下直後に送信ボタンを無効化し、処理中表示を出し、完了または失敗で必ず復帰する。営業中カラオケは保存ボタンを置かず、裏側のAjax保存で同じ復旧方針を満たす。失敗時は入力値とキューを消さず、同じ内容を再送できる。 |
| 2 | 実装済み | `/Orders`、営業中カラオケ、自由入力明細は「画面内ドラフト」を正式な操作単位にする。追加、数量変更、削除は即座に画面へ反映し、未送信ドラフトを `departmentId`、`businessDayId`、`slipId`、画面種別を含むキーで `localStorage` に保存する。登録成功時だけ該当ドラフトを削除する。 |
| 3 | 実装済み | 登録はドラフトをまとめて1回のPOST/RPCで送る。注文は既存の複数卓キューを維持し、カラオケと自由入力明細も同じく「複数行を一括保存」するRPCを用意する。営業中カラオケは最後の操作から短時間後に差分だけ自動保存し、1タップごとに保存RPCを呼ぶ実装にはしない。 |
| 4 | 実装済み | 候補データは画面初期表示でまとめて渡す。卓、商品、出勤キャスト、営業日状態はRazor表示時に取得し、操作中の候補選択や数量変更では追加RPCを呼ばない。営業中トップは一覧に必要な列だけを取得し、詳細内訳は伝票詳細で取得する。 |

| スコープ | 実装済み | `GoogleDrive:Scopes` を追加し、未指定時はDriveスコープを既定値とする。emailスコープは認証設定側で追加する。 |

| prefetch | 実装済み | `prefetch=1` の場合は先読み扱いにし、成功時は204、認証失敗時は401を返す。画面遷移は起こさない。 |
| 認証失敗 | 実装済み | 通常プレビューでDrive認証が不足する場合、親画面を `/Login?forceGoogle=true` へ遷移させるHTMLを返す。 |
| スキャンミス | 実装済み | 領収書画面からDB上の論理削除として処理し、入力対象から除外する。Driveファイル削除は行わない。 |

## 13. 主要データフロー

| フロー | 状態 | 仕様 |
| --- | --- | --- |
| 店舗選択 | 実装済み | `/Settings` -> `get_store_departments` -> Cookie/localStorage保存 -> `ILocalSettingsProvider` が各Repositoryへ店舗IDを供給する。 |
| 伝票作成 | 実装済み | `/` POST -> `EnsureCurrentAsync` -> 営業日自動作成 -> `create_store_slip` -> `/Slips/Edit` へ遷移する。 |
| 注文登録 | 実装済み | `/Orders` または伝票詳細 -> 商品一覧取得 -> 対象伝票を含む注文payload生成 -> Edge Function経由で `add_store_order_lines` を実行する。`/Orders` で複数卓が同じキューに混在する場合は、注文行ごとの `slip_id` で登録する。 |
| 会計確定 | 実装済み | 伝票詳細 -> Edge Function経由で `confirm_store_checkout` を実行し、伝票状態と会計金額を更新する流れへ寄せる。指名価格は会計額へ加算し、自由入力明細は会計合計額へ直接加減する。自由入力明細とカラオケは通常商品とは別枠で会計に表示する。 |
| 領収書印刷 | 一部実装 | 会計確定 -> 領収書印刷データ作成 -> `ReceiptPrinter:BridgeUrl` の端末側ブリッジアプリへ非同期送信する。印刷失敗時も会計確定は完了させる。ペアリング済みSII製レシートプリンターへの詳細APIと再印刷画面は後続仕様で定義する。 |
| 営業日締め | 実装済み | `/Closing` POST -> 領収書入力完了を含む画面側条件確認 -> `close_business_day` を実行し、DB側でも条件検証して締める。 |
| 領収書入力 | 実装済み | `/Closing/Receipts` -> Driveプレビュー -> DocManagement契約に沿った仕訳payload作成 -> `quick_enter_receipt` の `p_journal_payload` として送信し、領収書ステータスを完了にする。未入力領収書は営業日締めのブロック条件とする。 |
