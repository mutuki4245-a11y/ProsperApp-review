# ProsperApp システム仕様書

作成日: 2026-07-03
対象: ProsperApp 店舗用アプリ
用途: 開発引継ぎ

## 1. 文書の位置づけ

本書は ProsperApp のシステム構成、画面、主要コンポーネント、外部連携、RPC/SQL運用を整理する。業務要件は `Docs/要件定義書.md`、作業時の最新方針は `HANDOFF.md` を参照する。

状態区分は以下の通り。

| 状態 | 意味 |
| --- | --- |
| 実装済み | 現行コード、DB、または運用設定に実装が確認できる仕様 |
| 方針 | 現行方針として維持する仕様 |

## 4. 認証・認可

| 項目 | 状態 | 仕様 |
| --- | --- | --- |
| 認証方式 | 実装済み | Cookie認証を既定schemeとし、Google OAuth設定がある場合はGoogleをchallenge schemeにする。 |
| Google設定不足 | 実装済み | `GoogleDrive:ClientId` または `GoogleDrive:ClientSecret` が不足する場合、Google challengeを開始しない。 |
| 許可判定 | 実装済み | `GoogleAuthOptions.IsAllowed` が `AllowedEmails` と `AllowedDomains` を照合する。 |
| Cookie検証 | 実装済み | Cookie principal検証時にGoogle設定または許可条件を満たさない場合、principalをrejectしてSessionをclearする。 |
| Google token | 実装済み | Google access tokenは認証ticket作成時にSessionの `GoogleDriveAccessToken` へ保存する。 |
| 認可 | 実装済み | `MapRazorPages().RequireAuthorization()` によりRazor Pageを原則認証必須にする。`/Login` はPageModelの `[AllowAnonymous]` で認証前アクセスを許可する。 |
| logout | 実装済み | `/logout` はSessionをclearし、Cookie認証をsign outする。returnUrlはローカルURLのみ許可する。 |

## 7. Supabase RPC / Edge Function仕様

| 項目 | 状態 | 仕様 |
| --- | --- | --- |
| 呼び出し経路 | 方針 | 業務RPC呼び出しはEdge Function経由へ寄せる。Edge FunctionがSupabase RPCを実行し、アプリ側は直接テーブルRESTを呼ばない。 |
| Repository境界 | 実装済み | 画面と業務処理はRepositoryインターフェースを経由し、RPC名、payload、レスポンスparseをRepository/Infrastructure側へ集約する。 |
| API key | 方針 | Supabase SecretKeyはサーバー/Edge側のみで扱い、ブラウザへ露出させない。 |
| PublishableKey | 方針 | `Supabase:PublishableKey` は低権限読み取りを分ける場合だけ追加する任意キーとする。 |
| レスポンス | 実装済み | 配列系RPCはJSON配列としてparseし、scalar系RPCはbody文字列から数値等に変換する。 |
| エラー | 実装済み | HTTP失敗、parse失敗、例外を `SupabaseRpcResult` に正規化し、Repository側で利用者向け文言へ変換する。 |
| RLS/RPC | 方針 | DB側はRLSを有効化し、アプリ操作はEdge Function経由の `security definer` RPCで制御する。 |

主要RPCは機能単位で以下を利用する。

| 機能 | 状態 | RPC |
| --- | --- | --- |

## 9. Google Drive連携

| 項目 | 状態 | 仕様 |
| --- | --- | --- |
| 認証 | 実装済み | Google OAuth access tokenをSessionに保存し、Drive API呼び出しに使う。 |
| スコープ | 実装済み | `GoogleDrive:Scopes` を追加し、未指定時はDriveスコープを既定値とする。emailスコープは認証設定側で追加する。 |
| プレビュー | 実装済み | `/DrivePreview/{driveFileId}` がDriveファイルを取得し、Content-TypeとContent-Dispositionを設定してinline返却する。 |
| prefetch | 実装済み | `prefetch=1` の場合は先読み扱いにし、成功時は204、認証失敗時は401を返す。画面遷移は起こさない。 |
| 認証失敗 | 実装済み | 通常プレビューでDrive認証が不足する場合、親画面を `/Login?forceGoogle=true` へ遷移させるHTMLを返す。 |
| スキャンミス | 実装済み | 領収書画面からDB更新とDriveファイル操作を組み合わせて除外する。 |

## 12. 主要データフロー

| フロー | 状態 | 仕様 |
| --- | --- | --- |
| 店舗選択 | 実装済み | `/Settings` -> `get_store_departments` -> Cookie/localStorage保存 -> `ILocalSettingsProvider` が各Repositoryへ店舗IDを供給する。 |
| 伝票作成 | 実装済み | `/` POST -> `EnsureCurrentAsync` -> 営業日自動作成 -> `create_store_slip` -> `/Slips/Edit` へ遷移する。 |
| 注文登録 | 方針 | `/Orders` または伝票詳細 -> 商品一覧取得 -> 注文payload生成 -> Edge Function経由で `add_store_order_lines` を実行する流れへ寄せる。 |
| 会計確定 | 方針 | 伝票詳細 -> Edge Function経由で `confirm_store_checkout` を実行し、伝票状態と会計金額を更新する流れへ寄せる。 |
| 営業日締め | 方針 | `/Closing` POST -> 画面側条件確認 -> Edge Function経由で `close_business_day` を実行し、DB側でも条件検証して締める流れへ寄せる。 |
| 領収書入力 | 方針 | `/Closing/Receipts` -> `get_pending_receipts` -> Driveプレビュー -> Edge Function経由で `quick_enter_receipt` または `mark_receipt_scan_mistake` を実行する流れへ寄せる。 |
