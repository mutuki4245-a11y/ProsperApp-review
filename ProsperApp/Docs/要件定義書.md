# ProsperApp 要件定義書

作成日: 2026-07-03
対象: ProsperApp 店舗用アプリ
用途: 開発引継ぎ

## 1. 文書の位置づけ

本書は ProsperApp の業務要件を、現行実装と既定方針が分かる形で整理した開発引継ぎ用ドキュメントである。実装詳細は `Docs/システム仕様書.md`、作業方針やSQL/RPC参照情報の最新メモは `HANDOFF.md` も参照する。

状態区分は以下の通り。

| 状態 | 意味 |
| --- | --- |
| 実装済み | 現行コード、DB、または運用設定に実装が確認できる要件 |
| 方針 | `HANDOFF.md` または現行構成から今後も維持する前提の要件 |

## 2. システム目的

| 項目 | 状態 | 要件 |
| --- | --- | --- |
| 店舗業務の一元化 | 実装済み | 営業中の伝票管理、注文、会計、締め作業を店舗スタッフが同一アプリ上で処理できるようにする。 |
| 営業中操作の優先 | 実装済み | ルート `/` を営業中画面とし、当日伝票一覧、伝票起こし、勤怠管理導線を優先して表示する。 |
| 現場端末の役割分担 | 方針 | 現場運用は営業中画面を操作する端末1台と、注文入力用の `/Orders` 端末複数台を前提にする。営業中端末は伝票作成、当日伝票一覧、カラオケ簡易入力、会計導線、締め導線を扱い、注文端末は既存open伝票への注文登録に集中する。 |
| 締め作業の集約 | 実装済み | 酒代入力、勤怠確認、キャスト売上額調整、領収書入力、営業日締めを `/Closing` 配下に集約する。 |
| マスタ設定の分離 | 実装済み | キャスト情報、商品情報は営業フローの必須ステップではなく、上部タブの `マスタ設定` から開く任意管理領域とする。 |
| DBアクセスの統制 | 実装済み | アプリからのDB操作は Supabase RPC を `prosper-rpc` Edge Function経由で実行する。REST RPC fallbackと直接テーブルREST操作は持たない。 |

## 3. 利用者と権限

| 利用者 | 状態 | 要件 |
| --- | --- | --- |
| 店舗スタッフ | 実装済み | Googleログイン後、営業中画面、伝票、注文、締め作業を操作できる。 |
| 管理者 | 実装済み | `/Settings` で管理者設定を解除し、店舗選択、管理者モード、勤怠刻み、キャスト売上額調整設定を保存できる。 |
| 非管理者 | 実装済み | 商品管理ではカテゴリ編集操作を表示せず、カテゴリ保存POSTも拒否する。 |
| 許可アカウント | 実装済み | Googleログインは `GoogleAuth:AllowedEmails` または `GoogleAuth:AllowedDomains` に該当するメールアドレスだけを許可する。 |

## 4. 業務範囲

| 業務領域 | 状態 | 範囲 |
| --- | --- | --- |
| 店舗選択 | 実装済み | Supabaseの店舗マスタから利用店舗を選択し、端末ローカル設定として保存する。 |
| 営業日管理 | 実装済み | 現在営業日を取得し、営業入力時に営業日がなければ自動作成する。未締めの前営業日がある場合は新規営業日を作らず締め作業へ誘導する。 |
| 勤怠 | 実装済み | 出勤キャスト、出勤時刻、退勤時刻、送り利用有無を管理する。退勤時刻は締め前に必須確認する。 |
| 伝票管理 | 実装済み | 卓番、客、指名キャスト、注文、会計状態を伝票単位で管理する。 |
| 注文入力 | 実装済み | open伝票を選択し、カテゴリ別の商品ボタンから注文キューへ追加して一括登録する。 |
| 会計 | 実装済み | 伝票詳細から会計開始と現金会計確定を行う。 |
| 締め作業 | 実装済み | 未会計伝票、酒代、勤怠、キャスト売上額調整、領収書入力完了を確認して営業日を締める。 |
| 領収書簡易入力 | 実装済み | 未処理領収書を表示し、Google Driveプレビューを見ながら日付、金額、科目、摘要などを入力する。入力内容はDocManagement契約payloadとして組み立て、ProsperAppのRPCへ渡す。 |
| スキャンミス除外 | 実装済み | スキャンミスはDB上の論理削除として扱い、領収書入力対象から除外する。 |
| 勤怠入力改善 | 実装済み | キャスト追加はチェックボックスで複数名を一括登録でき、出勤時刻と退勤時刻は店舗営業時間に合わせた初期値と24:00以降表記で選択できるようにする。 |
| 指名入力改善 | 実装済み | 指名種別は本指名を既定値とし、同伴の時間区分と指名価格を明示的に選択できるようにする。指名価格は毎回選択し、会計額へ加算する。 |
| 注文入力改善 | 実装済み | `/Orders` では違う卓のオーダーも同じキューへ追加して一括登録でき、バック対象商品のキャスト選択では「なし」を選べるようにする。 |
| 会計額調整 | 実装済み | 通常商品とは別枠の自由入力明細を用意し、名前と価格を入力して会計額の調整や値引きに使えるようにする。商品マスタには登録せず、価格は負値も許容し、当面は会計合計額へ直接加減する。 |
| カラオケ | 実装済み | カラオケは通常商品とは別枠で伝票/会計に表示し、1回200円として扱う。商品マスタには登録せず、入力と表示は通常商品と分ける。 |
| 会計時領収書印刷 | 一部実装 | 会計時にSII製レシートプリンターへ領収書印刷要求を送れるようにする。印刷はSII Receipt Web Server相当の端末側ブリッジアプリを介して、ペアリング済みプリンターへ送る。印刷失敗時も会計確定は完了扱いとする。正式API、レイアウト、再印刷画面は後続仕様で定義する。 |

### 5.3 営業中

| --- | --- | --- |

| F-SALES-03 | 実装済み | 伝票作成時に営業日がなければ、店舗営業日の正午切替ルールに基づいて自動作成する。 |
| F-SALES-04 | 実装済み | 当日伝票一覧から伝票詳細へ遷移できる。 |
| F-SALES-05 | 実装済み | 営業中画面から勤怠管理へ遷移できる。 |
| F-SALES-06 | 実装済み | 営業中画面では卓ごとの会計額を常に隠し、画面右下寄りの固定オーバーレイボタンに触れている間だけ会計額を表示する。 |
| F-SALES-07 | 実装済み | 営業中画面ではカラオケを通常商品とは別枠で簡易入力でき、伝票行の `+` / `-` ボタンで数量を増減できる。数量変更は画面へ即時反映し、手動保存ボタンを置かず、短時間のデバウンス後に差分だけ自動保存する。伝票詳細へ遷移する前にも未保存分の保存を短く試みる。カラオケは1回200円とする。 |

| F-CLOSE-05 | 実装済み | 領収書入力は営業日締めの必須条件とし、未入力領収書がある場合は営業日締めを実行できない。 |

| F-CLOSE-07 | 実装済み | 領収書入力完了を含む営業日締め条件は、画面POSTと `close_business_day` RPCの両方で検証する。 |

| F-CLOSE-09 | 実装済み | 勤怠時刻選択では、出勤時刻は19:00、退勤時刻は24:00をUI初期値にする。選択肢は各初期値の前後12時間を表示し、24:00以降は25:00、26:00のように表記する。 |

## 6. 非機能要件

| 分類 | 状態 | 要件 |
| --- | --- | --- |
| セキュリティ | 実装済み | Cookie認証とGoogle OAuthを利用し、全Razor Pageを認証必須にする。 |
| DB権限 | 実装済み | RLSは有効化し、アプリ用操作は `security definer` RPCで制御する。アプリ側RPCはEdge Function経由に限定し、直接PostgREST RPC実行権限は付与しない。 |
| 秘密情報 | 方針 | Supabase RPCキー、Google認証情報、Azure publish profileはリポジトリへ保存しない。 |
| 店舗スコープ | 実装済み | 主要RPCのpayloadには `p_department_id` を含め、店舗単位で処理する。 |
| 可用性 | 方針 | 動作確認はAzure App Serviceへデプロイした環境で行う。ローカル起動を前提にしない。 |
| 操作性 | 実装済み | スマートフォン/PWA利用を想定したviewport、manifest、apple-touch-icon、処理中オーバーレイを備える。 |
| 現場操作レスポンス | 実装済み | `/Orders`、営業中カラオケ、自由入力明細は、画面内ドラフトへ即時反映する。営業中カラオケは手動保存を置かず、最後の操作から短時間後に差分だけPOST/RPCで自動保存する。1タップごとに保存通信を発生させない。 |
| 端末間同期 | 方針 | 営業中画面1台と `/Orders` 複数台の運用では、端末間の共有状態はDB/RPC保存後のデータを基準にする。localStorageや画面内ドラフトは端末内だけで完結させ、他端末へ直接同期しない。 |
| 送信復旧 | 実装済み | 注文登録、勤怠保存、会計確定、カラオケ数量保存、自由入力明細保存は、送信中の二重送信を防ぎ、失敗時も入力値と未送信ドラフトを保持して再送できるようにする。 |
| 画面初期データ | 実装済み | 卓、商品、出勤キャスト、営業日状態など操作中に使う候補は画面初期表示で取得し、候補選択や数量変更のたびに追加RPCを呼ばない。 |
| 保守性 | 実装済み | 画面はRazor Pages、業務DTOは `Features`、外部I/Oは `Infrastructure` と `Endpoints` に分離する。 |

## 7. 外部サービス要件

| サービス | 状態 | 要件 |
