# ProsperApp 要件定義書

作成日: 2026-07-03
対象: ProsperApp 店舗用アプリ
用途: 開発引継ぎ

## 1. 文書の位置づけ

本書は ProsperApp の業務要件を、現行実装と既定方針が分かる形で整理した開発引継ぎ用ドキュメントである。実装詳細は `Docs/システム仕様書.md`、作業方針やSQL/RPC参照情報の最新メモは `HANDOFF.md` も参照する。

状態区分は以下の通り。

| 状態 | 意味 |
| --- | --- |
| 実装済み | 現行コード、DB、または運用設定に実装が確認できる要件 |
| 方針 | `HANDOFF.md` または現行構成から今後も維持する前提の要件 |

## 2. システム目的

| 項目 | 状態 | 要件 |
| --- | --- | --- |
| 店舗業務の一元化 | 実装済み | 営業中の伝票管理、注文、会計、締め作業を店舗スタッフが同一アプリ上で処理できるようにする。 |
| 営業中操作の優先 | 実装済み | ルート `/` を営業中画面とし、当日伝票一覧、伝票起こし、勤怠管理導線を優先して表示する。 |
| 締め作業の集約 | 実装済み | 酒代入力、勤怠確認、キャスト売上額調整、領収書入力、営業日締めを `/Closing` 配下に集約する。 |
| マスタ設定の分離 | 実装済み | キャスト情報、商品情報は営業フローの必須ステップではなく、上部タブの `マスタ設定` から開く任意管理領域とする。 |
| DBアクセスの統制 | 実装済み | アプリからのDB操作は原則 Supabase RPC を利用し、`SupabaseRpcClient` でEdge Function経由へ切り替え可能にする。直接テーブルREST操作は避ける。 |

## 3. 利用者と権限

| 利用者 | 状態 | 要件 |
| --- | --- | --- |
| 店舗スタッフ | 実装済み | Googleログイン後、営業中画面、伝票、注文、締め作業を操作できる。 |
| 管理者 | 実装済み | `/Settings` で管理者設定を解除し、店舗選択、管理者モード、勤怠刻み、キャスト売上額調整設定を保存できる。 |
| 非管理者 | 実装済み | 商品管理ではカテゴリ編集操作を表示せず、カテゴリ保存POSTも拒否する。 |
| 許可アカウント | 実装済み | Googleログインは `GoogleAuth:AllowedEmails` または `GoogleAuth:AllowedDomains` に該当するメールアドレスだけを許可する。 |

## 4. 業務範囲

| 業務領域 | 状態 | 範囲 |
| --- | --- | --- |
| 店舗選択 | 実装済み | Supabaseの店舗マスタから利用店舗を選択し、端末ローカル設定として保存する。 |
| 営業日管理 | 実装済み | 現在営業日を取得し、営業入力時に営業日がなければ自動作成する。未締めの前営業日がある場合は新規営業日を作らず締め作業へ誘導する。 |
| 勤怠 | 実装済み | 出勤キャスト、出勤時刻、退勤時刻、送り利用有無を管理する。退勤時刻は締め前に必須確認する。 |
| 伝票管理 | 実装済み | 卓番、客、指名キャスト、注文、会計状態を伝票単位で管理する。 |
| 注文入力 | 実装済み | open伝票を選択し、カテゴリ別の商品ボタンから注文キューへ追加して一括登録する。 |
| 会計 | 実装済み | 伝票詳細から会計開始と現金会計確定を行う。 |
| 締め作業 | 実装済み | 未会計伝票、酒代、勤怠、キャスト売上額調整、領収書入力完了を確認して営業日を締める。 |
| 領収書簡易入力 | 実装済み | 未処理領収書を表示し、Google Driveプレビューを見ながら日付、金額、科目、摘要などを入力する。入力内容はDocManagement連携契約に従い、管理入力としてDBへ反映する。 |
| スキャンミス除外 | 実装済み | スキャンミスはDB上の論理削除として扱い、領収書入力対象から除外する。 |

## 5. 機能要件

### 5.1 ログイン

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-LOGIN-01 | 実装済み | `/Login` を除くRazor PageとDriveプレビューendpointは認証済みユーザーだけが利用できる。 |
| F-LOGIN-02 | 実装済み | Google OAuth設定が不足している場合、OAuthへ進まず `/Login` に設定不足を表示する。 |
| F-LOGIN-03 | 実装済み | Google認証失敗、許可外アカウント、リモート失敗は `/Login` にエラー表示する。 |
| F-LOGIN-04 | 実装済み | `/logout` でセッションとCookie認証を破棄する。 |

### 5.2 端末設定

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-SET-01 | 実装済み | `/Settings` は固定パスワード `4245` で管理者設定を解除する。 |
| F-SET-02 | 実装済み | 店舗設定は `ProsperApp.LocalSettings` としてCookieとlocalStorageに保存する。 |
| F-SET-03 | 実装済み | サーバー処理ではCookieの `StoreDepartmentId` を優先し、ない場合は `Supabase:StoreDepartmentId` にフォールバックする。 |
| F-SET-04 | 実装済み | 勤怠時刻の選択肢は端末設定の `AttendanceMinuteStep` に従う。 |
| F-SET-05 | 実装済み | キャスト売上額調整では、売上基準と分配方式を端末設定から利用する。 |

### 5.3 営業中

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-SALES-01 | 実装済み | 営業中画面は営業日、未会計数、会計済数のサマリーを表示する。 |
| F-SALES-02 | 実装済み | 営業中画面から卓番、来店時刻、客名、指名、メモを入力して伝票を作成できる。 |
| F-SALES-03 | 実装済み | 伝票作成時に営業日がなければ、店舗営業日の正午切替ルールに基づいて自動作成する。 |
| F-SALES-04 | 実装済み | 当日伝票一覧から伝票詳細へ遷移できる。 |
| F-SALES-05 | 実装済み | 営業中画面から勤怠管理へ遷移できる。 |

### 5.4 伝票詳細

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-SLIP-01 | 実装済み | 伝票詳細は客、指名、注文、会計の情報を同一画面で確認できる。 |
| F-SLIP-02 | 実装済み | 客を追加し、客名を更新し、退店時刻を登録できる。 |
| F-SLIP-03 | 実装済み | 指名キャストを追加できる。 |
| F-SLIP-04 | 実装済み | 注文を追加し、注文行を取消できる。 |
| F-SLIP-05 | 実装済み | 会計開始後、現金預かり額を入力して会計確定できる。 |

### 5.5 注文入力

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-ORDER-01 | 実装済み | `/Orders` でopen伝票を卓番として選択できる。 |
| F-ORDER-02 | 実装済み | 商品カテゴリ別の商品ボタンから注文キューへ追加できる。 |
| F-ORDER-03 | 実装済み | 同じ商品はキュー上で数量加算し、一括登録後は卓番選択へ戻る。 |

### 5.6 マスタ設定

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-MST-01 | 実装済み | `/Management` はキャスト情報と商品情報への入口を表示する。 |
| F-MST-02 | 実装済み | キャスト設定は `/Management/Casts` に配置し、有効キャスト一覧、キャスト作成、キャスト削除を扱う。 |
| F-MST-03 | 実装済み | 商品設定は `/Management/Items` に配置し、商品カテゴリ、商品、価格、キャストバック設定を管理する。 |
| F-MST-04 | 実装済み | 商品名は店舗内uniqueとして扱う。 |
| F-MST-05 | 実装済み | 商品は追加、削除、並び替えで運用し、注文履歴は商品マスタを再参照しない。 |

### 5.7 締め作業

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-CLOSE-01 | 実装済み | `/Closing` は酒代入力、勤怠確認、キャスト売上額調整、領収書入力を独立パネルで表示する。 |
| F-CLOSE-02 | 実装済み | 酒代は0円以上の整数として保存できる。酒代がない場合も0円で入力済みにする。 |
| F-CLOSE-03 | 実装済み | 勤怠確認では退勤時刻と送り利用有無を保存できる。 |
| F-CLOSE-04 | 実装済み | キャスト売上額調整は会計済みかつ指名キャストがいる伝票を対象に、専用ページとモーダルで保存する。 |
| F-CLOSE-05 | 実装済み | 領収書入力は営業日締めの必須条件とし、未入力領収書がある場合は営業日締めを実行できない。 |
| F-CLOSE-06 | 実装済み | 営業日締めは、未会計伝票0、酒代入力済み、勤怠1名以上、退勤未入力0、キャスト売上額調整済み、領収書入力完了を満たす場合だけ実行できる。 |
| F-CLOSE-07 | 実装済み | 領収書入力完了を含む営業日締め条件は、画面POSTと `close_business_day` RPCの両方で検証する。 |

### 5.8 領収書入力

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-REC-01 | 実装済み | `/Closing/Receipts` は未処理領収書を1件ずつ表示し、次へ進める。 |
| F-REC-02 | 実装済み | Google Drive PDFはアプリサーバー経由の `/DrivePreview/{driveFileId}` で表示する。 |
| F-REC-03 | 実装済み | 領収書入力は `C:\Users\mutuk\Desktop\DocManagement\docs\field-app-contract.md` の契約に従い、証憑ID、会社、部門、仕訳、証憑関連をDBへ反映する。 |
| F-REC-04 | 実装済み | スキャンミスはDB上の論理削除として処理し、領収書入力対象から除外する。 |
| F-REC-05 | 方針 | `Sql/quick_entry_account_master_updates.sql` は領収書簡易入力で使う科目・補助科目の現在定義を確認する参照資料として扱う。 |
| F-REC-06 | 実装済み | DocManagement側の管理入力・補完・修正結果は、`save_journal_payload` 契約の `journal_entries`、`journal_entry_lines`、`document_journal_links` として保存する。 |

## 6. 非機能要件

| 分類 | 状態 | 要件 |
| --- | --- | --- |
| セキュリティ | 実装済み | Cookie認証とGoogle OAuthを利用し、全Razor Pageを認証必須にする。 |
| DB権限 | 実装済み | RLSは有効化し、アプリ用操作は `security definer` RPCで制御する。アプリ側RPCはEdge Function経由へ切り替え可能にする。 |
| 秘密情報 | 方針 | Supabase SecretKey、Google認証情報、Azure publish profileはリポジトリへ保存しない。 |
| 店舗スコープ | 実装済み | 主要RPCのpayloadには `p_department_id` を含め、店舗単位で処理する。 |
| 可用性 | 方針 | 動作確認はAzure App Serviceへデプロイした環境で行う。ローカル起動を前提にしない。 |
| 操作性 | 実装済み | スマートフォン/PWA利用を想定したviewport、manifest、apple-touch-icon、処理中オーバーレイを備える。 |
| 保守性 | 実装済み | 画面はRazor Pages、業務DTOは `Features`、外部I/Oは `Infrastructure` と `Endpoints` に分離する。 |

## 7. 外部サービス要件

| サービス | 状態 | 要件 |
| --- | --- | --- |
| Supabase | 実装済み | 業務RPCはEdge Function経由へ切り替え可能にする。SecretKeyはサーバー/Edge側で扱い、PublishableKeyは低権限読み取りを分ける場合だけ追加する。 |
| DocManagement | 実装済み | 領収書入力は `C:\Users\mutuk\Desktop\DocManagement` の `document-api` Edge Function契約に従って管理入力をDBへ反映する。 |
| Google OAuth | 実装済み | Googleログイン、メールアドレス許可、Driveアクセスtoken保存に利用する。 |
| Google Drive | 実装済み | 領収書PDFプレビューと先読みに利用する。 |
| Azure App Service | 方針 | 本番/確認環境として利用し、環境変数でSupabase/Google設定を注入する。 |
| GitHub Actions | 実装済み | `main` pushまたは手動実行でAzure App Serviceへデプロイするワークフローを持つ。 |

## 8. 運用制約

| 項目 | 状態 | 制約 |
| --- | --- | --- |
| SQL管理 | 方針 | SQLファイルは現在のDB内容を確認するための参照資料として扱う。DB反映はCodexがCLI等で実行する。 |
| Azure設定 | 実装済み | `Supabase__PublishableKey` 以外の必要環境変数は実装済みとして扱う。PublishableKeyは低権限読み取りを分ける場合だけ追加する。 |
| ローカル設定 | 実装済み | 店舗選択など端末固有設定はCookie/localStorageに保存され、サーバー永続DBには保存しない。 |
| キー方式 | 方針 | Supabaseの新API key方式を前提にし、SecretKeyはブラウザへ露出させない。 |
