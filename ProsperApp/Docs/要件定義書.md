# ProsperApp 要件定義書

作成日: 2026-07-03
対象: ProsperApp 店舗用アプリ
用途: 開発引継ぎ

## 1. 文書の位置づけ

本書は ProsperApp の業務要件を、現行実装と既定方針が分かる形で整理した開発引継ぎ用ドキュメントである。実装詳細は `Docs/システム仕様書.md`、作業方針やSQL/RPC参照情報の最新メモは `HANDOFF.md` も参照する。

会計フロー第1段階と営業中一覧ハブは、アプリ、リモートDB、Edge Function、Azure App Serviceへ適用済みである。営業中トップ `/` の一覧・編集モーダル・会計モーダルを入口にし、旧 `/Slips/Edit` は削除済みである。P1受入確認とプリンター実機別の印字調整は継続中である。

状態区分は以下の通り。

| 状態 | 意味 |
| --- | --- |
| 実装済み | 現行コード、DB、または運用設定に実装が確認できる要件 |
| 適用済み（受入継続中） | アプリ、リモートDB、Edge Functionへ適用済みで、実機またはP1受入確認を継続している要件 |
| 置換済み | 旧実装を削除し、記載した新しい導線または契約へ置き換えた要件 |
| 一部実装 | アプリ側の処理はあるが、外部側の正式仕様、画面、または運用定義が残っている要件 |
| 運用方針 | 実装作業ではなく、現行運用や開発時に維持する前提 |
| 後続仕様 | 未実装で、別途仕様定義してから実装する要件 |
| 検討候補 | 効果や破棄契機を確認したうえで実装判断する改善案 |

## 2. システム目的

| 項目 | 状態 | 要件 |
| --- | --- | --- |
| 店舗業務の一元化 | 実装済み | 営業中の伝票管理、注文、会計、締め作業を店舗スタッフが同一アプリ上で処理できるようにする。 |
| 営業中操作の優先 | 実装済み | ルート `/` を営業中画面とし、当日伝票一覧、伝票起こし、勤怠管理導線を優先して表示する。 |
| 営業フロー事故防止 | 運用方針 | 締め作業と管理画面より先に、営業中トップ、営業中一覧ハブ、注文端末、会計完了までの誤卓、未保存、誤会計を防ぐ。見た目の刷新より、保存状態、対象伝票、会計内容を取り違えないことを優先する。 |
| 現場端末の役割分担 | 運用方針 | 現場運用は営業中画面を操作する端末1台と、注文入力用の `/Orders` 端末複数台を前提にする。営業中端末は伝票作成、当日伝票一覧、カラオケ簡易入力、会計導線、締め導線を扱い、注文端末は既存open伝票への注文登録に集中する。 |
| 締め作業の集約 | 実装済み | 酒代入力、勤怠確認、キャスト売上額調整、領収書入力、営業日締めを `/Closing` 配下に集約する。 |
| マスタ設定の分離 | 実装済み | キャスト情報、商品情報は営業フローの必須ステップではなく、上部タブの `マスタ設定` から開く任意管理領域とする。 |
| DBアクセスの統制 | 実装済み | アプリからのDB操作は Supabase RPC を `prosper-rpc` Edge Function経由で実行する。REST RPC fallbackと直接テーブルREST操作は持たない。 |

## 3. 利用者と権限

| 利用者 | 状態 | 要件 |
| --- | --- | --- |
| 店舗スタッフ | 実装済み | Googleログイン後、営業中画面、伝票、注文、締め作業を操作できる。 |
| 管理者 | 実装済み | `/Settings` で管理者設定を解除し、店舗選択、画面モード、管理者モードを端末に保存できる。勤怠刻みとキャスト売上額調整設定は店舗別マスターで管理する。 |
| 非管理者 | 実装済み | 商品管理ではカテゴリ編集操作を表示せず、カテゴリ保存POSTも拒否する。 |
| 許可アカウント | 実装済み | Googleログインは `GoogleAuth:AllowedEmails` または `GoogleAuth:AllowedDomains` に該当するメールアドレスだけを許可する。 |

## 4. 業務範囲

| 業務領域 | 状態 | 範囲 |
| --- | --- | --- |
| 店舗選択 | 実装済み | Supabaseの店舗マスタから利用店舗を選択し、端末ローカル設定として保存する。 |
| 営業日管理 | 実装済み | 現在営業日を取得し、営業入力時に営業日がなければ自動作成する。未締めの前営業日がある場合は新規営業日を作らず締め作業へ誘導する。 |
| 勤怠 | 実装済み | 出勤キャスト、出勤時刻、退勤時刻、送り利用有無を管理する。退勤時刻は締め前に必須確認する。 |
| 伝票管理 | 実装済み | 卓番、客、指名キャスト、注文、会計状態を伝票単位で管理する。 |
| 注文入力 | 実装済み | open伝票を選択し、カテゴリ別の商品ボタンから注文キューへ追加して一括登録する。 |
| 営業中一覧ハブ | 一部実装 | 営業中トップには会計伝票・会計準備中・支払確定・領収書再発行の会計導線を実装済みである。客、指名、自由入力明細などの編集を卓行展開と専用モーダルだけで完結させる部分は後続とする。 |
| 会計 | 適用済み（受入継続中） | 会計開始から会計取消までを営業中トップ `/` の会計モーダルで行う。`/Slips/Edit` は会計に使わない。 |
| 会計伝票と会計準備中 | 適用済み（受入継続中） | 会計フローは会計伝票出力と会計確定の2ステップである。会計伝票出力時に退店時刻を選択して会計内容を固定し、伝票を `checkout_ready` にして一切の伝票編集を止める。`store.issue_checkout_statement` は最新状態の検証、退店時刻固定、未退店客の補完、印刷用 `print_data` と会計画面用 `review_data` の返却までを1RPCで行い、成功後は直ちに物理印刷を開始する。物理印刷状態は同一端末のlocalStorageだけで管理し、会計確定の条件にしない。会計準備中は再印刷、会計準備解除、決済への移行を選べ、会計確定は `checkout_ready` から `checked_out` へのDB操作である。 |
| 会計伝票再印刷 | 適用済み（受入継続中） | 会計伝票は会計準備中であれば自由に再印刷でき、紙面に `再印刷` 表記や印刷履歴を持たない。同一端末では保存済み印刷データを使い、ローカルデータ欠落・破損・別ブラウザ利用時だけ `store.get_checkout_statement_print_data` で再生成する。会計確定または会計準備解除の成功時は端末内印刷記録を削除する。 |
| 会計準備中と営業日締め | 適用済み（受入継続中） | 通常の営業日締めでは `open` と `checkout_ready` の両方を未会計伝票として扱い、1件でもあれば締めを拒否する。管理者モードの締め条件無視はこの条件も迂回する。 |
| 会計前確認 | 適用済み（受入継続中） | 明細確認は会計伝票で行い、会計確定画面は支払方法、現金預かり、釣銭、確定操作に集中する。`store.confirm_checkout` は `checkout_ready` だけを受け付け、`open` から直接確定しない。 |
| 0円会計 | 適用済み（受入継続中） | 会計額が0円の場合は決済方法を登録しない0円会計として確定する。会計伝票と領収書は0円で出力し、「請求なし 0円」と表示する。 |
| サービス料計算 | 適用済み（受入継続中） | サービス料は有効な `store_order_lines` 全体の小計に20%を掛けて円単位へ丸める。標準商品、カラオケ、指名料金を含み、自由入力明細の加算・値引きは対象に含めない。`base_amount = order_subtotal_amount + service_charge_amount`、`applied_adjustment_amount = max(adjustment_amount, -base_amount)`、`total_amount = base_amount + applied_adjustment_amount` とする。 |
| 決済方法入力 | 適用済み（受入継続中） | 0円以外の会計では支払方法別入力額の合計が会計額と一致する場合だけ確定できる。初回選択時だけ残額を初期入力し、利用者の入力後は自動上書きしない。現金、CAT、PAYPAYの3種類を固定seedし、RPCは同一方法の重複を拒否する。 |
| 締め作業 | 実装済み | 未会計伝票、酒代、勤怠、キャスト売上額調整、領収書入力完了を確認して営業日を締める。 |
| 領収書簡易入力 | 実装済み | 未処理領収書を表示し、Google Driveプレビューを見ながら日付、金額、科目、摘要などを入力する。入力内容はDocManagement契約payloadとして組み立て、ProsperAppのRPCへ渡す。 |
| スキャンミス除外 | 実装済み | スキャンミスはDB上の論理削除として扱い、領収書入力対象から除外する。 |
| 勤怠入力改善 | 実装済み | キャスト追加はチェックボックスで複数名を一括登録でき、出勤時刻と退勤時刻は店舗営業時間に合わせた初期値と24:00以降表記で選択できる。 |
| 指名入力改善 | 実装済み | 指名種別は店舗別DBマスタの有効行から選択し、指名料金を明示的に選択できる。指名料金は毎回選択し、システム商品として注文行に自動追加して会計額へ加算する。 |
| 指名種別別キャストバック | 実装済み | 店舗別DBマスタで指名種別、表示名、同伴時刻、バック単価、有効/無効を管理し、指名登録時に有効な単価を営業実績へスナップショット保存する。 |
| 料金・バック用語 | 運用方針 | 会計額へ加算する料金は指名料金、指名時にキャストへ支払うバックは指名バック、商品注文時にキャストへ支払う通常バックはドリンクバック、商品注文バック対象が当該伝票の指名キャストだった場合のバックは担当バックと呼び分ける。 |
| 注文入力改善 | 実装済み | `/Orders` では違う卓のオーダーも同じキューへ追加して一括登録でき、バック対象商品のキャスト選択では「なし」を選べるようにする。注文端末には標準商品だけを表示し、システム商品だけのカテゴリは表示しない。 |
| 会計額調整 | 実装済み | 通常商品とは別枠の自由入力明細を用意し、名前と価格を入力して会計額の調整や値引きに使えるようにする。商品マスタには登録せず、価格は負値も許容し、当面は会計合計額へ直接加減する。 |
| カラオケ | 実装済み | カラオケは商品マスタ上のシステム商品として扱い、1回200円固定で通常の商品小計に含める。サービス料20%の対象とし、伝票/会計ではオーダー明細として表示する。 |
| 会計時領収書印刷 | 適用済み（受入継続中） | 会計確定時の領収書印刷データ作成、SII Web SDK Serverへのブラウザ直接印刷、80mm紙向けの領収書レイアウト、印刷失敗時も会計確定を取り消さない処理、同一ブラウザの端末内通知、確定済み伝票からの手動再発行、明示再試行時だけの `再試行` 表記を実装済み。DBの印刷状態や印刷ジョブは作らない。 |

## 5. 機能要件

### 5.1 ログイン

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-LOGIN-01 | 実装済み | `/Login` を除くRazor PageとDriveプレビューendpointは認証済みユーザーだけが利用できる。 |
| F-LOGIN-02 | 実装済み | Google OAuth設定が不足している場合、OAuthへ進まず `/Login` に設定不足を表示する。 |
| F-LOGIN-03 | 実装済み | Google認証失敗、許可外アカウント、リモート失敗は `/Login` にエラー表示する。 |
| F-LOGIN-04 | 実装済み | `/logout` でセッションとCookie認証を破棄する。 |

### 5.2 端末設定

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-SET-01 | 実装済み | `/Settings` は固定パスワード `4245` で管理者設定を解除する。 |
| F-SET-02 | 実装済み | 店舗設定は `ProsperApp.LocalSettings` としてCookieとlocalStorageに保存する。 |
| F-SET-03 | 実装済み | サーバー処理ではCookieの `StoreDepartmentId` を優先し、ない場合は `Supabase:StoreDepartmentId` にフォールバックする。 |
| F-SET-04 | 実装済み | 勤怠時刻の選択肢は店舗別マスターの `attendance_minute_step` に従う。 |
| F-SET-05 | 実装済み | キャスト売上額調整では、売上基準と分配方式を店舗別マスターの `cast_sales_amount_basis` と `cast_sales_split_mode` から利用する。 |
| F-SET-06 | 実装済み | 端末設定の画面モードは、営業中端末向けの `sales-management` と注文端末向けの `order-entry` を持つ。`order-entry` 端末は営業中トップへアクセスしても `/Orders` へ誘導する。 |

### 5.3 営業中

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-SALES-01 | 適用済み（受入継続中） | 営業中画面は営業日、未会計数、会計済数のサマリーを表示する。`checkout_ready` は未会計数に含め、一覧上は通常の `open` 伝票と分けて会計準備中として表示する。 |
| F-SALES-02 | 実装済み | 営業中画面から卓番、来店時刻、客名、指名、メモを入力して伝票を作成できる。 |
| F-SALES-03 | 実装済み | 伝票作成時に営業日がなければ、店舗営業日の正午切替ルールに基づいて自動作成する。 |
| F-SALES-04 | 実装済み | 当日伝票一覧から伝票詳細へ遷移できる。 |
| F-SALES-05 | 実装済み | 営業中画面から勤怠管理へ遷移できる。 |
| F-SALES-06 | 実装済み | 営業中画面では卓ごとの会計額を常に隠し、画面右下寄りの固定オーバーレイボタンに触れている間だけ会計額を表示する。 |
| F-SALES-07 | 実装済み | 営業中画面ではカラオケを伝票行の `+` / `-` ボタンで簡易入力できる。数量変更は画面と会計額へ即時反映し、手動保存ボタンや短周期の自動保存は置かず、アプリ内遷移や他フォーム送信の前に未保存分を保存する。カラオケは商品マスタ上のシステム商品で、1回200円かつサービス料対象とする。 |
| F-SALES-11 | 実装済み | 未保存のカラオケ数量は、店舗・営業日・伝票に紐付けた端末ごとのlocalStorage下書きとして画面再読込後も復元する。DB最新状態で対象伝票が `open` でない場合、保存成功時、または利用者が明示破棄した場合は下書きを削除する。 |
| F-SALES-08 | 運用方針 | 営業中画面は1台の営業中端末が中心的に操作する。営業中端末のカラオケ数量や会計額は操作直後にローカル表示へ即時反映し、保存通信はアプリ内遷移や他フォーム送信の前にまとめて実行する。複数注文端末からの注文はDB保存後の再取得または画面更新で反映する。 |
| F-SALES-09 | 実装済み | 営業中トップのカラオケ数量が未保存の場合、アプリ内リンク遷移や他フォーム送信の前に保存し、保存成功後だけ遷移または送信を続ける。ブラウザ再読み込みは運用上不要な操作として防止し、未保存時は警告対象にする。 |
| F-SALES-10 | 後続仕様 | 営業中一覧を営業中一覧ハブとして扱い、卓行をその場で展開して客、指名、注文合計、注文件数、自由入力明細合計、会計伝票出力を確認できるようにする。注文明細の時刻一覧や細かい内訳は必要時に開く。 |
| F-SALES-11B | 一部実装 | 注文端末から登録された注文は、通常表示では10秒ポーリングとフォーカス復帰で営業中一覧へ反映する。会計伝票出力は `store.issue_checkout_statement` 自身が対象伝票の最新状態を検証してから処理する。卓行展開の差分通知は後続とする。 |
| F-SALES-12 | 適用済み（受入継続中） | 会計伝票は店舗表示名、卓番、入店時刻、退店時刻、客数、明細、金額サマリーだけを印字する。オーダー明細は商品名、数量、単価、金額のまとめ行とし、顧客名、指名キャスト名・種別、バック対象キャスト、注文時刻一覧は印字しない。会計確認画面の注文行だけにバック対象キャストを表示する。 |
| F-SALES-13 | 適用済み（受入継続中） | 会計伝票の自由入力明細は通常オーダーとは別枠にし、摘要と符号付き金額を個別行で印字する。 |
| F-SALES-14 | 適用済み（受入継続中） | 会計伝票の金額サマリーは小計、サービス料、内消費税（10%）、合計の4段表示とする。内消費税は `round(total_amount * 10 / 110)` の参考表示で、合計に加算しない。支払方法別金額、現金預り金、釣銭は印字しない。 |
| F-SALES-15 | 後続仕様 | 営業中トップに見込み売上を参考表示する。見込み売上は、取消以外の伝票の会計額合計のみを表示する。会計額はその時点で計算できる税込・サービス料込みの最終請求額とし、営業中の参考値なので大きく目立たせない。更新は営業中一覧ハブと同じ10秒ポーリング/フォーカス復帰で行う。 |

### 5.4 伝票詳細

| ID | 状態 | 要件 |
| --- | --- | --- |
| F-SLIP-01 | 実装済み | 伝票詳細は客、指名、注文、自由入力明細を同一画面で確認・編集できる補助画面である。会計情報と会計操作は営業中トップの会計モーダルへ分離している。 |

| F-PRINT-15 | 将来候補 | 営業日締め後を含む確定済み伝票の検索・再試行一覧は将来候補として残す。今回の後続実装範囲には入れず、入口画面、実装時期、検索RPCの契約も未決定とする。実装時は営業日、会計確定日時、卓番、会計額を表示し、取消済み伝票を対象外にする。`checkout_id` と `slip_no` は内部管理に留める。 |
| F-PRINT-16 | 適用済み（受入継続中） | 発行者マスタ列の追加、画面実装前のサンプル値のseed、会計確定時の `store_checkouts.issuer_snapshot jsonb` 保存を、最初の会計SQL/RPC切替と同じ変更単位で行う。発行者マスタの編集画面だけを後続タスクに分ける。会計確定と同じトランザクションで、発行者情報を `issuer_snapshot` へ値コピーして固定する。 |
| F-PRINT-17 | 適用済み（受入継続中） | 発行者スナップショットの法人名、登録番号、店舗表示名、住所、電話番号が欠けた場合は、保存値を補完せず紙面上だけ `未設定` と明示する。ロゴは適格簡易請求書の必須事項ではないため、未設定表示の対象にせず、空欄または初期サンプルロゴのまま扱う。 |
| F-PRINT-18 | 本番移行条件 | 適格簡易請求書としての保存項目、紙面表示、税率別集計、再試行運用を、本番移行前に税理士へ確認する。確認前の仕様はテスト運用の前提であり、税務上の最終判断に代えない。 |

| 秘密情報 | 運用方針 | Supabase RPCキー、Google認証情報、Azure publish profileはリポジトリへ保存しない。 |

| 可用性 | 運用方針 | 動作確認はAzure App Serviceへデプロイした環境で行う。ローカル起動を前提にしない。 |
| 操作性 | 実装済み | スマートフォン/PWA利用を想定したviewport、manifest、apple-touch-icon、処理中オーバーレイを備える。 |
| 現場操作レスポンス | 実装済み | `/Orders`、営業中カラオケ、自由入力明細は、画面内の操作結果へ即時反映する。営業中カラオケは手動保存や短周期の自動保存を置かず、アプリ内遷移や他フォーム送信の前に差分だけPOST/RPCで保存する。自由入力明細は専用モーダル内で1件入力して保存を完結させる。会計前の追加確認RPCは発生させない。 |
| RPC回数抑制 | 運用方針 | 会計フローの快適性を保つため、会計確定前に追加の事前確認RPCを増やさない。厳密な一致確認は会計確定RPC内で行い、RPC回数は増やさずに事故防止を担保する。 |
| 操作ロック | 実装済み | 登録RPCや画面遷移待ちでは共通の処理中オーバーレイと送信ボタン無効化で追加操作を止める。個別画面では、共通ロックを通らない独自fetch、部分更新、特殊な遷移処理だけを追加確認対象にする。 |
| 端末間同期 | 運用方針 | 営業中画面1台と `/Orders` 複数台の運用では、端末間の共有状態はDB/RPC保存後のデータを基準にする。localStorageや画面内ドラフトは端末内だけで完結させ、他端末へ直接同期しない。 |
| 送信復旧 | 実装済み | 注文登録、勤怠保存、会計確定、カラオケ数量保存、自由入力明細保存は、送信中の二重送信を防ぐ。失敗時は入力値を消さず、自由入力明細はモーダル内で再送または保存せず破棄を選べるようにする。 |
| 画面初期データ | 実装済み | 卓、商品、出勤キャスト、営業日状態など操作中に使う候補は画面初期表示で取得し、候補選択や数量変更のたびに追加RPCを呼ばない。 |
| 保守性 | 実装済み | 画面はRazor Pages、業務DTOは `Features`、外部I/Oは `Infrastructure` と `Endpoints` に分離する。 |

## 9. 実装予定・方針のみの整理

### 9.1 後続仕様・検討候補

| 項目 | 状態 | 整理 |
| --- | --- | --- |
| レシートプリンター正式連携 | 適用済み（受入継続中） | 会計時の印刷要求データ作成、SII Web SDK Serverへのブラウザ直接印刷、80mm紙向けの指定項目レイアウト、失敗時に会計を取り消さない処理、確定済み伝票からの手動再発行、明示再試行時だけの `再試行` 表記を実装済み。領収書の印刷状態、印刷ジョブ、印刷履歴をDBへ保存しない。残件はプリンター実機別の印字調整、SII Web SDK Serverの端末起動・接続設定、およびリモートDB/Edge Functionの適用である。 |
| 当日出勤キャスト候補キャッシュ | 実装済み | `store.get_order_attending_casts` は店舗別・営業日別に `IMemoryCache` へ初回成功時だけ保持する。勤怠保存、退勤情報保存、営業日開始、営業日締めの成功時に営業日単位キャッシュを破棄する。 |
| 営業中一覧と注文対象伝票の再取得削減 | 実装済み | 営業中トップは `store.get_business_day_snapshot` をRazor初期表示後に取得し、編集操作とカラオケ下書きは `store.flush_business_home_changes` でまとめて保存する。`/Orders` の `store.get_order_entry_slips` もRazor初期表示をブロックせず、初回Ajax、フォーカス復帰、10秒ごとの表示中自動更新で取得する。保存成功POST直後の同期再取得は行わず、`/Orders` で候補から消えた伝票は選択と未送信キューから外す。 |
