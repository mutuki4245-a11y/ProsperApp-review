# 設計改善計画

## 目的

営業中から会計完了までの実装は動作範囲が広く、PageModel、Razor、ブラウザJS、Repository、RPCの役割が混ざりやすい状態です。今後の修正で同じ不具合を繰り返さないように、問題点、変更方針、実装順をこの文書に固定します。

## 問題点

### 1. PageModelに業務変換が残っている

会計確定前の合計計算、確認スナップショットJSON、領収書印刷要求の組み立てが `Pages/Slips/Edit.Checkout.cshtml.cs` にありました。PageModelは画面入力、検証結果、遷移を扱うだけに寄せたい一方で、会計データの形を作る実装も抱えていました。支払行の既定化、退店時刻合成、現金受取額検証も同じPageModelに残っていました。

この状態だと、会計RPCの確認データと印刷データを別々に直してしまい、同じ会計内容を違う形で扱うリスクがあります。

### 2. 注文キューの処理順が呼び出し側に漏れている

`/Orders` と伝票詳細のオーダー追加では、POSTされたJSONをパースし、必要なら既存入力へ戻し、正規化し、業務検証する順序がPageModel側に散っています。

JSONパースと正規化が別の浅い関数として見えているため、呼び出し側が順序を誤ると、空キュー、重複行、バック対象キャストの扱いが画面ごとにずれる可能性があります。自由入力明細も同じく、POSTされたJSON、フォームfallback、正規化、検証の順序がPageModel側に残っていました。指名追加でも、指名種別マスタ、出勤キャスト候補、指名料金の検証がPageModelに残っていました。客追加、退店、客名更新でも、時刻合成、入力整形、対象客検証がPageModelに残っていました。

### 3. 営業中トップの状態処理が大きい

営業中トップは一覧差分更新、カラオケ未保存状態、伝票作成モーダル、再印刷待ちなどを同じ画面に持っています。現状の方針は妥当ですが、今後の修正では、状態の読み書き単位を小さくしないと、カラオケ保存や再印刷待ちのような端末内状態が他の画面操作に影響しやすくなります。

### 4. レシート印字レイアウトがブラウザ実装へ寄っている

SII Web SDK Serverへの接続自体はブラウザの責務ですが、印字文字列の整形までJSに寄りすぎると、将来のプリンター差し替えや実機別調整時に比較しづらくなります。接続と印字データ整形を分ける余地があります。

## 変更方針

- DB保存、店舗スコープ、会計確定の厳密な一致確認はRPC側に残します。
- アプリ内だけで完結する変換は、不要なadapterや抽象化を増やさず、深いmoduleへ寄せます。
- PageModelは、画面入力、ModelState、Load、Redirect、TempDataに集中させます。
- JSONB/JSON配列の正規化は、呼び出し側へ手順を散らさず、入口moduleに集約します。
- JSの整理は、画面の操作保証が変わらない範囲で、状態管理と外部接続を分ける順に進めます。
- 変更ごとに `dotnet build --no-restore` と `git diff --check` を通します。JS変更を含む場合は構文確認も追加します。

## 実装順

1. 会計表示moduleを追加し、会計合計、確認スナップショットJSON、領収書印刷要求をPageModelから切り出す。
2. 注文キューmoduleを深くし、POST JSONの読み取り、fallback、正規化を `IOrderQueueService` の入口に集約する。
3. 営業中トップのカラオケ保存状態を、画面遷移時保存の方針に合わせて小さいJS moduleへ分ける。
4. SII印刷JSのうち、接続処理と印字レイアウト処理を分け、実機調整時の比較点を減らす。
5. 自由入力明細のPOST JSON読み取り、フォームfallback、正規化、検証をPageModelから切り出す。
6. 指名追加の正規化、候補キャスト名補完、マスタ/出勤/料金検証をPageModelから切り出す。
7. 客追加、退店、客名更新の入力整形、時刻合成、対象客検証をPageModelから切り出す。
8. 会計入力の支払行既定化、退店時刻合成、支払額/受取額検証をPageModelから切り出す。

## 今回実装する範囲

今回は1から20までを、挙動を変えない範囲で順に実装します。

- 1は `CheckoutDocumentBuilder.Build` へ切り出し、会計合計、確認スナップショットJSON、領収書印刷要求の元データを `CheckoutDocument` にまとめます。PageModelは合計計算とスナップショット生成の順序を知らず、画面表示と確定結果の受け渡しだけを扱います。
- 2は `IOrderQueueService.ReadPostedQueue` へ集約し、正規化手順と画面別の検証policyは注文キューmoduleの内部実装として隠します。
- 3は営業中トップの一覧取得、カラオケドラフト、遷移時保存を `business-home.js` へ移し、伝票追加モーダルを `create-slip-modal.js` へ移します。Razor側はURL、候補、表示フラグなどのconfig注入だけにします。
- 4は `sii-receipt-layout.js` を追加し、領収書本文の組み立てをSII接続処理から分けます。
- 5は `SlipOrderLineEditor` へ、標準注文行の削除可否と注文数量訂正の正規化・検証を集約します。
- 6は `SlipAdjustmentEditor` へ、自由入力明細のJSON読み取り、fallback選択、正規化、検証を集約します。
- 7は `SlipNominationEditor` へ、指名追加の空行除去、指名種別の補正、キャスト名補完、候補検証を集約します。
- 8は `SlipCustomerEditor` へ、客追加、退店、客名更新の入力整形、表示用初期行、時刻初期値、時刻合成、対象客検証を集約します。
- 9は `CheckoutInputEditor` へ、会計入力の支払行既定化、退店時刻初期値、退店時刻合成、支払額/受取額検証を集約します。支払方法テンプレートもこのmodule内に隠し、PageModelが支払方法補正ルールを知らない形にします。
- 10は `slip-adjustments.js` へ、自由入力明細モーダルの行追加、JSON同期、未保存確認、保存中表示を `slips-edit.js` から切り出します。伝票詳細の残りJSは注文、会計、客、指名の操作だけを扱う状態へ近づけます。
- 11は `slip-checkout.js` へ、会計モーダルの退店時刻同期、決済方法選択、現金受取ステップ、釣銭表示、会計取消確認を `slips-edit.js` から切り出します。会計のブラウザ操作は会計moduleだけを見れば追える形にします。
- 12は `slip-nominations.js` へ、指名追加モーダル、指名行の再採番、出勤キャスト選択モーダルを `slips-edit.js` から切り出します。指名のブラウザ操作は指名moduleだけを見れば追える形にします。
- 13は `slip-customers.js` へ、客追加モーダル表示、客名更新の部分送信、客一覧部分更新後のvalidation再初期化を `slips-edit.js` から切り出します。客のブラウザ操作は客moduleだけを見れば追える形にします。
- 14は残った注文追加、注文数量訂正、注文バック選択だけを扱う `slips-edit.js` を `slip-orders.js` へ改名し、ファイル名とmoduleの実態を一致させます。
- 15は `TerminalSaveStatus` を `site.js` に追加し、営業中トップ、伝票詳細、注文端末、締め最終パネルの保存状態表示を同じinterfaceへ集約します。呼び出し側は `saved`、`dirty`、`saving`、`error` を明示し、保存状態の文言と `data-save-state` の対応を散らさない形にします。
- 16は `/Orders` の注文端末操作を `order-entry.js` へ切り出し、Razorは初期JSONとscript読み込みだけを持つ形にします。卓番再取得、注文キュー、バック対象キャスト選択、カテゴリ切り替えは注文端末moduleだけを見れば追える形にします。
- 17は `CastSelectModal` を追加し、伝票作成、指名追加、伝票詳細注文、注文端末に散っていた出勤キャスト選択モーダルのDOM生成を同じinterfaceへ集約します。呼び出し側は候補、表示名、選択時処理だけを渡し、空表示とバック対象の「指定なし」行はmodule内へ隠します。
- 18は `MoneyText` を `site.js` に追加し、UI表示用の金額丸めと `円` 表示を同じinterfaceへ集約します。営業中トップ、伝票詳細注文、伝票詳細会計、注文端末、締め最終パネルはこのmoduleを使い、プリンター紙面用の印字整形は別moduleの責務として残します。
- 19は `OrderBackText` を追加し、伝票詳細注文と注文端末のキュー表示に散っていたバック対象キャスト表示、ドリンクバック、担当バックの文言と金額計算を同じinterfaceへ集約します。
- 20は `StoreOrderItemOption.CastBackSummaryText` を追加し、注文端末と伝票詳細の商品ボタンに散っていたバック対象商品の静的説明文を同じinterfaceへ集約します。
